## 1. Analytical boundary: what a Flock / ALPR map shows and does not show (`CAM-06`)

Public interest in locating Automated License Plate Reader (ALPR) deployments—frequently referred to colloquially as "Flock camera maps" after Flock Safety, alongside other ALPR vendors such as Motorola Solutions / Vigilant, Genetec AutoVu, and Leonardo / ELSAG—relies primarily on community-mapped OpenStreetMap (`man_made=surveillance`, `surveillance:type=ALPR`) directories and regional extracts (such as DeFlock / `tiles.dontgetflocked.com`).

Under `AGENTS.md` §2 and §6 and requirement `CAM-06`, OIA enforces strict epistemological boundaries on these records:

1. **Mapped directory assertions only, distinct from `CAM-01`/`CAM-02` viewable feeds:** `CAM-01` and `CAM-02` govern viewable camera feeds, still frames, and archives that can serve as direct observation evidence. By contrast, an ALPR directory node under `CAM-06` represents a community-mapped assertion of where surveillance/ALPR hardware is installed and its reported OpenStreetMap tags. It is not a verified hardware deployment inventory, and it does **not** provide access to camera video, still frames, license-plate read logs, retention databases, or live operational telemetry.
2. **No home-interior views or restricted endpoint probing (`CAM-01`, `CAM-06`):** ALPR directory mapping ingests only public OpenStreetMap nodes and published community catalog extracts. OIA must never probe camera IP addresses, guess credentials, or attempt to connect to restricted ALPR vendor endpoints.
3. **Manufacturer attribution vs. generic ALPR classification (`CAM-06`):** Users frequently search for "Flock cameras" when investigating corridor coverage, while OpenStreetMap tags `surveillance:type=ALPR` across multiple manufacturers and often leaves `manufacturer` untagged. OIA classifies each mapped node's manufacturer state explicitly:
   - `FlockSafety`: `manufacturer`, `brand`, or `operator` explicitly identifies Flock Safety (e.g., `Flock Safety`, `Flock`).
   - `OtherNamed(String)`: another explicit manufacturer is recorded (e.g., `Motorola Solutions`, `Genetec`, `Leonardo`).
   - `Unspecified`: the node is tagged as an ALPR camera (`surveillance:type` includes `ALPR`), but no manufacturer tag is present.
   Filtering a map view to `Flock Safety only` must display a visible **local-filter chip** (`CASE-02`) and report how many additional ALPR nodes in the same viewport are `OtherNamed` or `Unspecified`, so an untagged ALPR node is never silently mistaken for absence of cameras or promoted into a confirmed Flock Safety device.
4. **Community mapping is not exhaustive coverage (`CAM-06`, `GEO-02`, `GEO-05`):** An empty viewport in a covered region means **zero mapped ALPR nodes in the queried extract**, not proof that no physical cameras exist on that road. Outside the extract's geographic bounds, the state is `NoCoverage`, not `Empty`.
5. **Synthetic test fixtures must never attribute surveillance hardware to real organizations (`AGENTS.md` §2):** Repository fixtures (`fixtures/cameras/alpr/new-meridian-corridor-fixture.json`) use a fictional city (`New Meridian Synthetic Corridor`), fictional operators (`New Meridian Municipal Transit Authority (Synthetic)`, `Aegis Harbor District Patrol (Synthetic)`, etc.), `.invalid` URLs, a reserved synthetic OpenStreetMap node ID range (`>= 900_000_000_000`, specifically `900_000_000_101`..`900_000_000_199`), and explicit per-record markers (`"synthetic": true` on the node object plus `"note": "SYNTHETIC FIXTURE - NOT OBSERVED"` and `"oia:synthetic": "true"` in `tags`) so extracted nodes can never be mistaken for real observations or real agency deployments.

### 2.2 Upstream source terms and reuse conditions (`AGENTS.md` §6, `CAM-06`, checked `2026-11-02`)

Before any runtime ingestion adapter contacts an external ALPR directory service, OIA records the source terms, rate-limit expectations, and four distinct operational conditions (**access**, **automated processing**, **retention**, and **redistribution**) for both upstream sources, alongside the Open Database License (ODbL 1.0) obligations checked on `2026-11-02`:

1. **OpenStreetMap via Overpass API (`https://overpass-api.de/api/interpreter`):**
   - **Consulted references (checked `2026-11-02`):** Overpass API Commons / Usage Policy (`https://dev.overpass-api.de/overpass-doc/en/preface/commons.html`), OpenStreetMap Wiki — Overpass API (`https://wiki.openstreetmap.org/wiki/Overpass_API`), and OpenStreetMap Copyright & License (`https://www.openstreetmap.org/copyright`).
   - **Usage policy and rate/slot management:** The public `overpass-api.de` instance is a shared community resource enforcing per-IP concurrent slot limits (typically 2 slots with cooldown windows) and server-side memory/time budgets, rejecting abusive bulk-scraping or planet-scale queries with HTTP `429 Too Many Requests` or `504 Gateway Timeout`.
   - **How OIA complies:** OIA rejects viewports wider than `MAX_VIEWPORT_DEGREES = 3.0°` (`ZoomRequired`) before any network call, snaps outward by `0.05°` (`QUERY_SNAP_DEGREES`) so small pans reuse the active snapshot, bounds Overpass QL with `[out:json][timeout:20]` and `out body 1500;` (`QUERY_LIMIT = 1500`), and enforces exponential retry backoff via `alpr_retry_delay_ms` (`30,000 ms` initial delay doubling up to `240,000 ms`) whenever an upstream query fails or is rate-limited.
2. **DeFlock vector-tile extract (`https://tiles.dontgetflocked.com`, `https://deflock.me`, `https://github.com/FoggedLens/deflock`):**
   - **Consulted references (checked `2026-11-02`):** DeFlock project site (`https://deflock.me`), DeFlock repository (`https://github.com/FoggedLens/deflock`), and the US/Canada vector-tile endpoint referenced in God's Eye View `src/layers/alpr/source.js` (`https://tiles.dontgetflocked.com/countries/{country}/{z}/{x}/{y}.mvt`).
   - **Published terms and attribution status:** DeFlock is a third-party community project redistributing an hourly US/Canada OpenStreetMap-derived ALPR extract (`man_made=surveillance` + `surveillance:type=ALPR`). Underlying camera node data is derived from OpenStreetMap and requires ODbL 1.0 attribution (`© OpenStreetMap contributors`, with source credit to DeFlock when its tile mirror is used). As checked on `2026-11-02`, `tiles.dontgetflocked.com` does not publish a separate standalone commercial tile SLA or bulk-scraping license; therefore, automated bulk pre-crawling or regional mirror scraping is **not** assumed to be permitted. Any interactive tile requests must remain strictly bounded to user-driven city viewports at `z9..=z12` with `DETAIL_MAX_TILES = 16` (`SOURCE_RECORD_LIMIT = 6000`), and operators may configure their own self-hosted extract or query Overpass directly.
3. **Four-condition source matrix (`CAM-06`, `AGENTS.md` §6):**

| Upstream source | Access condition | Automated processing condition | Retention condition | Redistribution condition |

### 2.3 ODbL 1.0 share-alike, derivative databases, and code-license boundary

- **Code license vs. data license (`D14`, `CAM-06`):** OIA's source code is dual-licensed under `MIT OR Apache-2.0` (`D14`), and the selectively ported `src/layers/alpr/*` algorithms from God's Eye View are licensed under the MIT License (`Copyright (c) Bilawal Sidhu`). **Neither OIA's code license nor God's Eye View's MIT code license covers OpenStreetMap or DeFlock camera data.**
- **ODbL 1.0 (`https://opendatacommons.org/licenses/odbl/1-0/`, checked `2026-11-02`) implications for retained cases and exported bundles (`REPRO-01`, `COLLAB-03`):**
  1. **Collective vs. Derivative Database boundary:** Under ODbL 1.0 §4.5 and §4.6, when OIA stores or exports an investigation bundle (`REPRO-01`) that keeps normalized OpenStreetMap ALPR records in a clearly separated, machine-readable table/manifest alongside independent non-OSM evidence (such as user field notes, news articles, or independent sensor tracks), the overall case archive functions as a **Collective Database**, while the filtered/normalized ALPR camera table itself is a **Derivative Database** of OpenStreetMap.
  2. **Attribution and notice:** Every workspace view, printed/HTML report (`COLLAB-02`), and exported bundle (`REPRO-01`) that includes OSM/DeFlock ALPR records must display `"© OpenStreetMap contributors, licensed under ODbL 1.0"` with a link to `https://www.openstreetmap.org/copyright` and `https://opendatacommons.org/licenses/odbl/1-0/`.
  3. **Share-alike and open offer on redistributed ALPR extracts:** If a user publishes or redistributes an exported bundle or report containing a Derivative Database of OSM ALPR nodes (or a Produced Work derived from it), the OSM-derived ALPR dataset portion remains licensed under ODbL 1.0, must not have technical protection measures (DRM) applied that restrict ODbL rights, and must include or offer the machine-readable normalized ALPR records (or the exact Overpass query / diff used to produce them) under ODbL 1.0. Independent non-OSM case records in the Collective Database remain under their own respective licenses.

## 3. Normalized record contract (`AlprCameraRecord`)

Every normalized ALPR directory node must preserve:

| Field | Type / domain | Contract |
| --- | --- | --- |
| `id` | `alpr:<osm_id>` (`u64 > 0`) | Canonical selection and deduplication identity within an OSM-backed catalog. Display labels (`ALPR-0101`) never replace `id`. |
| `osm_id` | `u64` (`> 0`) | Positive OpenStreetMap node identifier. Non-node elements (`way`, `relation`) or non-positive IDs are rejected by node normalization. Synthetic repository fixtures reserve `osm_id >= 900_000_000_000` (`SYNTHETIC_OSM_ID_FLOOR`). |
| `latitude_deg`, `longitude_deg` | `f64` (`[-90, 90]`, `[-180, 180]`, finite) | WGS84 horizontal position in degrees. Height is not provided by OSM ALPR nodes and must remain `None` (unknown) in domain records; terrain clamping is a presentation-only transform. |
| `coordinate_zoom` | `Option<u8>` | Finest tile zoom (`9..=12`) or `None` for unquantized Overpass/raw coordinates. Used by the precision cache so coarse tile reads (`z9` ≈ 19 m quantization) never degrade a previously observed `z12` (≈ 2 m) or exact coordinate. |
| `manufacturer` | `Option<String>` | Trimmed `manufacturer` or `brand` tag when non-empty; `None` when absent or whitespace-only. |
| `manufacturer_class` | `AlprManufacturerClass` | `FlockSafety`, `OtherNamed`, or `Unspecified`, derived deterministically from `manufacturer`, `brand`, and `operator` tags without mutating the raw strings. |
| `operator` | `Option<String>` | Trimmed `operator` tag (e.g., law enforcement agency, municipality, HOA); `None` when absent. |
| `camera_type` | `Option<String>` | Trimmed `camera:type` tag (e.g., `fixed`, `panning`); `None` when absent. |
| `zone` | `Option<String>` | Trimmed `surveillance:zone` tag (e.g., `traffic`, `street`, `parking`); `None` when absent. |
| `direction_deg` | `Option<f64>` | Compass bearing in `[0.0, 360.0)` degrees clockwise from true north. `360.0` normalizes to `0.0`. Blank/whitespace strings, out-of-range numbers (`< 0` or `> 360`), and cardinal words (`"N"`, `"NE"`) yield `None`. |
| `reference` | `Option<String>` | Trimmed `ref` tag; `None` when absent. |
| `last_verified` | `Option<String>` | Trimmed `check_date` or `survey:date` tag recording field verification. Must remain `None` when neither tag is present. |
| `osm_timestamp` | `Option<String>` | Upstream OSM element edit/extract timestamp. Never copied into `last_verified`. |
| `source_tag` | `Option<String>` | Trimmed `source` tag on the OSM node when supplied. |
| `note` | `Option<String>` | Trimmed `note` tag when present (carries `"SYNTHETIC FIXTURE - NOT OBSERVED"` on all repository fixture records). |
| `synthetic` | `bool` | `true` when the record originates from a synthetic fixture (`raw.synthetic`, `oia:synthetic=true`, `note` containing `"SYNTHETIC FIXTURE"`, or `osm_id >= 900_000_000_000`); `false` for live/extracted OSM records. |

## 4. Viewport bounding, tile zoom selection, and coverage semantics

1. **Bounded city-scale viewport:** Queries require a finite bounding box with `-90 <= south < north <= 90`, `-180 <= west < east <= 180`, and span `<= MAX_VIEWPORT_DEGREES + 2 * QUERY_SNAP_DEGREES` (`3.10°`). Wider viewports return `AlprCoverageStatus::ZoomRequired` before issuing any network request.
2. **Outward grid snapping and reuse:** Valid viewports snap outward to `QUERY_SNAP_DEGREES` (`0.05°`) so minor pans reuse the accepted snapshot without redundant upstream requests, provided the cached snapshot is fresh and its tile zoom is at most one level coarser than the new view's `alprDetailZoom`.
3. **Detail zoom selection (`z12` down to `z9`):** For tiled extracts, select the finest zoom in `12..=9` whose Web Mercator XYZ tile count for the viewport is `<= DETAIL_MAX_TILES` (`16`). If even `z9` requires more than `16` tiles, return `ZoomRequired`.
4. **Geographic extract coverage:** When querying a regional extract (e.g., US/Canada bounds `lat 17..=84`, `lon -180..=-50` with per-country TileJSON bounds), a viewport disjoint from the extract bounds returns `AlprCoverageStatus::NoCoverage` with zero network tile reads.
5. **Deterministic saturation capping:** If a viewport contains more than `query_limit` (`1,500`) cameras, records are ordered deterministically by equirectangular squared distance to the viewport center `(lat - center_lat)^2 + ((lon - center_lon) * cos(center_lat))^2` (with ascending `osm_id` tie-breaking), truncated to `query_limit`, and marked `AlprCoverageStatus::Saturated { total_matching, retained, omitted }`. A saturated result never caches its outer tile bounds as complete coverage.

## 5. Workspace map presentation and interaction (`UX-01`–`UX-05`, `CAM-06`)

The companion interactive map prototype ([flock-camera-map.html](../design/mockups/flock-camera-map.html)) applies the [workspace UI/UX design](../design/workspace-ui-ux.md) to the Cameras / Globe instrument using the fictional `New Meridian Synthetic Corridor` fixture:

- **Distinguishable manufacturer & bearing markers:** Every camera marker pairs color with shape/glyph and text labels so state is never color alone (`UX-03`):
   - `Flock Safety` (cyan `#45d1ff` solid diamond + `FLOCK` badge)
   - `Other named ALPR` (amber `#ffc06b` square + vendor badge)
   - `Unspecified ALPR` (muted slate `#a2b0bc` hollow ring + `UNSPEC` badge)
- **Explicit mapped-extract coverage wording:** The HUD reports `OUTCOME: COMPLETE · 8 of 8 mapped in extract` (rather than implying complete physical camera coverage of the road network).
- **Illustrative bearing wedges:** Drawn only for cameras with a numeric `direction_deg`, using a dashed boundary and explicit legend/inspector disclosure (`Illustrative 90 m / ±20° bearing wedge — not measured FOV or capture range`). Clean-evidence mode (`data-clean="true"`) hides illustrative wedges, grid rings, and selection brackets while keeping camera positions and provenance badges visible.
- **Visible local-filter chips (`CASE-02`):** Filtering by manufacturer (`All mapped ALPR`, `Flock Safety only`, `Other / unspecified`) or bearing availability displays an active local-filter chip in the canvas header alongside the unfiltered viewport totals.
- **Inspector provenance tabs:** Selecting any camera coordinates the map selection brackets, shared timeline marks (`survey:date` vs. `osmTimestamp`), and inspector (`Overview` and `Source & ODbL` tabs citing `CAM-06` and ODbL 1.0 conditions), while pushing onto the bounded route-back stack (`Alt+Left` or `← Back`).
