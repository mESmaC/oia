# Local desktop workbench

Implemented slice of [#16](https://github.com/mESmaC/oia/issues/16), following the owner's Tauri selection in [ADR 0008](../adr/0008-d01-workspace-renderer.md), plus a session-only witness presentation slice of [#27](https://github.com/mESmaC/oia/issues/27). `oia-app` opens a desktop window and connects the merged document and PNG/JPEG privacy kernels to real local files and the witness kernel to an in-memory account. It does not import files or testimony into a case or implement the persistent services owned by #10/#11/#14.

## Run

```text
cargo run -p oia-app --locked
```

On Windows, `.\scripts\run.ps1 run` launches the same app. `scripts/run.sh run` is the POSIX equivalent. `run PATH ...` retains the existing text-inspection behavior; the explicit spelling is `inspect PATH ...`. `search` remains the text CLI example. `oia --status` reports scope without opening a window. `cargo run -p oia-app --no-default-features --locked -- --status` works without desktop dependencies being compiled.

The pinned Rust toolchain is 1.99.0. First builds need the locked Cargo dependencies; subsequent cached builds may add `--offline`. The Windows desktop needs MSVC C++ build tools and WebView2. The UI has no npm, Node, development server, or network provider requirement. Linux/macOS need the usual Tauri system dependencies and have not been validated by this slice.

## Available workflows

The [local News desk](news-desk.md) (#156) adds explicit JSON-dossier import, filtered article-version reading, shared publication inventory and declared lineage inspection and provenance inspection. It is session-only, unreviewed, and has no connected feeds. The fictional example loads only on request.

1. **Document reader:** select a UTF-8 file through a native dialog, read line passages, search exact case-sensitive text, and select a match to focus its original source line. Byte offsets are zero-based/end-exclusive and remain anchored to the opened bytes. Pagination presents 100 passages at a time without changing extraction coverage.
2. **File privacy:** select a PNG/JPEG, inspect container classifications and coverage, choose removable metadata categories, and save a cleaned copy through a native dialog. The original stays unchanged. The existing kernels reinspect the output and check their exact container-preservation contracts before the copy is published. This is not full image decoding, content anonymization, or proof that every identifying field was removed.
3. **Witness capture:** capture one reported or simulated account with all FIELD-02 text fields, retain the initial version read-only, expose only an unassessed static explanation checklist through an explicit recorded transition, and append rationale-required revisions with expected-version checks. Rust owns identifiers and state. The account is memory-only and discarded on exit; this demonstrates workflow ordering but does not meet the durable-evidence host requirement. See [witness capture](witness-capture.md).
   - **Recreation prompt (`MEDIA-04`, A10 subset of #31):** with an account captured, the Witness instrument's Recreation panel builds a portable illustration brief from one retained version through the merged [recreation kernel](recreation-prompts.md) (`oia_media::recreation::export_recreation_prompt`). `src/recreation.rs` maps the chosen version into the kernel's input: every nonempty narrative line and each nonempty duration, direction, motion and sound field becomes a reported detail pinned to that version id, with the line number in its source note; location, reported time and conditions become reported scene, time and lighting context; apparent size becomes reported angular/relative scale with the physical size stated unknown; viewpoint and any unreported context field stay explicit unknowns naming the version, unless the user ties the field to an assumption they declared (assumption and rationale) in the panel; an assumption can never replace reported wording (`reported_field_assumed`). Declared unknowns (aspect and impact) are passed through verbatim. The adapter calls `derive_unknown_negative_keywords` over the unknown scene/time/viewpoint/lighting/scale context and those declarations, and exports the resulting source-bound exclusions in the portable text's separate negative-keyword section. Only the derived rationale copies gain the existing source label, so simulated, post-exposure and revised origins remain visible without rewriting the user's declarations; the readout reports the derived negative count alongside the exact text. The account's qualifications travel with the prompt: every pinned item's source note reads `witness-vN · reported testimony|simulated account[ · recorded after candidate explanations were exposed][ · revision rationale: …]`, and the prompt title carries the same label plus a statement that the identifiers are session-local, so the reported context lines (which have no note) and the saved file never present a simulated or post-exposure account as plain testimony; line breaks in a rationale are shown as visible `\u{..}` escapes in that label only. The kernel validates, including its single-line and control-character rules (a tab in the account is refused, not repaired, and the adapter names the narrative line or field first) and the fixed adapter limits (64 details, 16 assumptions, 16 unknowns, 128 KiB text, 256 KiB output; the declared text is measured before anything is copied), and renders the text; a refused build keeps the previous prompt and consumes no prompt version. The page shows the kernel's visible `ILLUSTRATIVE RECREATION` label and fidelity caveat, the source version with its origin and markers, each context field as reported, assumed or unknown, and the portable text verbatim in a read-only field. Context choices are bound to a declared assumption's stable row id, so removing another assumption cannot re-bind them. **Save prompt as text** writes exactly that text as a `.txt` through the native Save dialog, the single-operation worker and the same no-clobber staging as the image exports, and shows the path, byte length and SHA-256; a prompt superseded since it was shown is refused (`stale_prompt`). Identifiers are session-local (`prompt:witness-session-1`, `ver:recreation-N`, `case:local-session`), not case records. No image is generated or imported, no reference asset or conflicting variant is supported, and nothing is persisted.
4. **Presentation:** the shell follows [visual language v2](../design/visual-language-v2.md): a readout strip that states only view facts (source, byte hash, coverage, selection), a rail that lists unavailable instruments with a reason, an evidence canvas (reader or container map) with the inspector beside it, and a jobs strip whose text comes from the single worker's state. Selection is a bracket on the selected passage or container row; coverage is a meter with its numerator and denominator printed. Keyboard: Ctrl+O opens a document, Ctrl+I inspects an image, Ctrl+F searches the open document, F6 cycles regions, arrow keys move between inspector tabs. Effects and Focus toggles remove blur and the grid or hide the rail and inspector; neither changes any value. There is no animation or sound. Controls and coverage use glyphs and labels in addition to color. Source content is assigned as text, never HTML, and no inline style or script is used, so the CSP needs no `unsafe-inline`.

5. **Globe:** a CesiumJS globe over a bundled synthetic case with live NASA GIBS basemap tiles, sharper registered detail imagery when zoomed in, and a Rust-owned registry of context layers (the first is the `CAM-06` mapped ALPR camera directory over a synthetic fixture), documented separately in [globe-instrument.md](globe-instrument.md). It shares this shell (rail, readout strip, inspector, Effects and Focus) and the `oia-local-tools/1` envelope, and its Rust state is independent of the single file-operation worker below.
6. **Media forensics (Ctrl+M):** with an image snapshot open, `Run cues` runs the merged [still-image forensic cue kernel](image-forensics.md) (`oia_image_forensics::analyze`, `MEDIA-01` subset of #30) on the same retained bytes, under the single worker with cancellation and the 30-second deadline. The image is the canvas, served to the page by a Rust-owned read-only URI scheme keyed by the snapshot's SHA-256; repeated-block candidates are drawn over it as linked bracketed regions (selectable, Escape clears), the three RGB histograms are drawn as small multiples of the recorded bins with their maxima printed, and the inspector shows the analysis record, metadata cues and uninspected containers, each method's coverage, scope and limitations, and the kernel's limitations verbatim. The assessment is always the kernel's `inconclusive` and `unreviewed`; a JPEG report is always partial, as the kernel states. Running cues writes nothing. **Save JPEG residual PNG** in the Media inspector re-runs the same kernel on the retained JPEG snapshot with map emission enabled, quality 90 and gain 8, under the existing worker and deadline. The native Save dialog proposes a separate diagnostic PNG; existing destinations are refused by the same no-clobber staging used for cleanup. PNG inputs have no applicable JPEG residual map and the control is disabled. The exported kernel PNG retains embedded derivative-role, source SHA-256, profile, quality/gain/implementation and JPEG validation labels. The panel states the JPEG entropy/recovery limitation before export and shows the saved path, byte length, source hash and output hash afterward. This is a conventional derivative and partial decoder-output diagnostic, never an observation or authenticity verdict. The existing report and original image remain in place. No case or durable analysis record is created.

7. **Corpus search and citations (Ctrl+Shift+O):** `Open corpus` selects up to 20 UTF-8 files through the native multi-file dialog (2 MiB each, 8 MiB in total); a count or byte overflow, or a failed read, refuses the whole selection and keeps the previous corpus. The files are held as immutable snapshots in selection order, which is their slot order and not a source or version identity. The search field's scope control switches between the open document and the corpus when both are held. A corpus search runs the merged [`corpus::search_corpus`](document-corpus-search.md) matcher (the selected substring or whitespace-token mode) over every snapshot with one shared 200-match limit; the results panel groups matches by file with each file's outcome (`searched`, or `match_limit_reached` when the shared limit left it unsearched, which is never shown as an empty file) and its searched, unsearched and unextracted bytes, repeated in the inspector's Corpus tab. Selecting a match in another held file opens that snapshot in the reader without a dialog, so the match's byte anchors stay valid. The Citations tab adds a session-only record from the selected match (quote copied from the retained bytes) or checks a pasted byte range and quote against the open document through [`citations::validate_citations`](document-citations.md); a rejected citation is a record with the kernel's reason, not an operation failure, and nothing is repaired or searched. Each record states that it is a structural check of this session's retained bytes, not a source-version citation, entailment, authenticity or review; a copyable text form escapes hidden controls like the reader. Up to 100 records are held, valid and rejected alike, and discarded on exit.

The Documents **Match** selector chooses **Exact substring** (the default) or **Whole token (whitespace)** for both scopes. Both are exact and case-sensitive, with no case folding or Unicode normalization. Whole-token mode uses Unicode whitespace or LF-delimited passage edges as boundaries, keeps punctuation literal (`light` does not match `light,`), and refuses queries containing whitespace without trimming them. It is not linguistic word segmentation. The existing `find_text`/`find_token` and corpus kernels own these rules; the desktop adds no matching algorithm. Each request requires the typed `mode` (`exact_substring` or `whitespace_token`), and each response retains it. Unknown modes are rejected during IPC deserialization. Results describe the returned mode; changing it clears results and the selected match for both scopes, leaving citation records intact. The selector is keyboard accessible and disabled while a worker runs. Query-byte validation remains active after scope, mode and busy-state changes.

One document, one corpus, one image snapshot, and one witness account can be held at a time. Switching views retains them and the displayed search in memory; closing the process discards them. Witness capture rejects replacement of its initial account rather than clearing history. UI settings are also session-only. Reopening a changed source explicitly replaces the snapshot. A cancelled or failed open preserves the previous snapshot. No file is automatically reopened after restart.

## Provenance

Each successful file load receives a Rust-owned session-only `snapshot_ref`, distinct even for identical bytes, repeated selections of the same path, or reopening a corpus. Clones retain that reference and the selected file's name/path. Corpus buttons, matches, reader navigation and citation intents carry the reference plus the expected SHA-256; Rust resolves that exact held snapshot and rejects mismatches as `stale_input`. A hash is a byte-integrity check, not a file-selection identity. Replacing a corpus never reassigns an old reference to a new slot. An old snapshot still open in the reader remains citable as that original reader snapshot, but cannot be reopened through the replaced corpus. These references are not durable source-version IDs or an authorization mechanism.

The Rust side of this workbench (`src/local_tools/`, `src/desktop.rs`, `tauri.conf.json`, `capabilities/`, `build.rs`, `tests/local_tools.rs`, and the first draft of this document) was written by the Codex running-app session ([#16 claim 6591833455](https://github.com/mESmaC/oia/issues/16#issuecomment-6591833455)) and taken unchanged from its worktree on 2026-11-03. The project owner released that work to the visual-study session on 2026-11-03 ([#16 comment 6592993871](https://github.com/mESmaC/oia/issues/16#issuecomment-6592993871)), which delivered it in [PR #105](https://github.com/mESmaC/oia/pull/105) together with the `ui/` presentation layer and now maintains both.

## Departures from ADR 0008 §4

[ADR 0008](../adr/0008-d01-workspace-renderer.md) is Accepted, and this first build departs from two of its §4 rules. Both are interim and are owned by #14, which introduces the shared application services and the renderer-independent shell state.

| Rule | What the ADR requires | What this build does | Why, and follow-up |
| --- | --- | --- | --- |
| §4 rule 1 | `oia-app` (Rust) owns shared context, route stack, local filters, settings, and job states; the page draws state and sends intents. | The active instrument, reading page, selected passage or container row, the Effects and Focus toggles, and the busy flag live in `ui/app.js`; uncommitted witness form input lives in `ui/witness.js`. Rust owns the snapshots, the operation gate, cancellation, publication, and committed witness transitions. | There is no case, route stack, or job registry yet to hold them in. The page state is presentation state with no domain value and no persistence. #14 moves instrument, selection, and settings into the Rust shell state and the page becomes a projection of it. |
| §4 rule 2 | Every response carries a schema identifier, an outcome, and a coverage statement; types generated from Rust. | Successful responses carry `schema: "oia-local-tools/1"` and the DTO. File DTOs use `complete` and byte fields as the coverage statement; the witness DTO carries retained versions, exposure markers, and an explicit memory-only retention statement. Errors return a bare `ToolError { code, message }` with no envelope. Types are hand-matched in JavaScript, not generated. | The envelope and the generated types belong to the P0 contracts; adding a second, throwaway envelope here would create the duplicate the ADR forbids. #14 wraps errors in the same versioned envelope and generates the page's types. |

Related deferrals from review: the kernels' handling and target enums cross the transport as plain strings (`local_tools/privacy.rs`), including a `Debug` rendering of the JPEG segment kind; #14 should carry them as serde-serialised enums. The v2 typefaces (IBM Plex Mono, Inter) are not bundled; the page uses system stacks and loads nothing from the network. The Windows Save dialog may offer to replace an existing file; the export then refuses with `destination_exists` because OIA never overwrites, and the refusal says so.

## Boundary and limits

`src/witness.rs` owns the transient witness adapter and DTOs; `ui/witness.js` sends capture/revision/exposure intents and renders the returned account without creating a parallel domain model. `src/recreation.rs` holds the last validated recreation prompt and the fixed kernel limits; it reads the witness DTO, never the page's copy, and the page holds only uncommitted declarations until **Build prompt**. `src/local_tools/` is a stateless I/O/DTO adapter over the merged file kernels: bounded reads, immutable byte snapshots, SHA-256, kernel calls, typed errors and safe output staging. It introduces no case store, job service, query index or alternative extraction/cleanup algorithm. #14 can adopt these functions behind its shared service contracts. `src/desktop.rs` is the Tauri/native-dialog adapter; it owns the transient single-operation gate and publishes results only after a cancellation check. `ui/` draws Rust responses and sends intents; its local state is presentation (tabs, reading pages, focus, checked removal choices, uncommitted witness form input), not a parallel evidence model.

The application-specific transport envelope is `oia-local-tools/1`; Rust serializable structs are the schema, and JavaScript does not declare a duplicate domain type model. These are transient tool results, not persisted evidence envelopes or durable source-version IDs; witness identifiers are session-local only. A SHA-256 identifies bytes only; a local path is not a stable citation or source record. Publication, capture and event times are not invented from filesystem timestamps.

| Operation | Bound and visible effect |
| --- | --- |
| Text read | 2 MiB; oversized input rejected, never silently truncated |
| Extraction | 10,000 passages; remaining bytes explicitly reported as partial |
| Search | 512 UTF-8 query bytes, 200 matches, exact non-overlapping substring or whitespace-token matches within LF-delimited passages; a reached budget remains partial |
| Corpus | 20 files, 8 MiB of original bytes in total, each file under the text read bound; the 200-match limit is shared across the selection in slot order, and a count/byte overflow refuses the whole selection |
| Citations | One range and quote per check, 4,096 UTF-8 quote bytes, 100 session records; a quote or range the kernel rejects is recorded with its reason, never repaired |
| Image read/output | 16 MiB; bounded regular-file reads and no image decoding |
| Image container | 4,096 chunks/segments, 2 MiB metadata, 32,768 pixels per axis, 100 million pixels total |
| Forensic cues | The kernel's defaults with the 16 MiB input limit: 4 million decoded pixels, 8,192 px per axis, 128 MiB decoder allowance, 65,536 grid blocks, 100 candidates; a reached limit is reported as a stop or as partial coverage, never trimmed silently |
| Processing | One active worker; 30-second cooperative deadline after dialog selection; cancellation checked inside kernels and at publication |

File I/O and OS dialogs are not preemptible. Cancel requests prevent subsequent publication but may need the user to close an open dialog, or wait for an OS read to return. No fabricated progress percentage is displayed. Busy commands are rejected rather than queued. Cancellation and commit share the same lock: once an export has committed, a later cancellation does not undo it. These workers are not durable jobs and do not claim restart recovery.

The reader escapes hidden controls and bidi formatting for display only; exact source bytes/offsets stay intact. Text and image tools do not silently substitute a parser, infer missing metadata, or convert an unsupported image profile into a successful cleanup. In particular, many camera JPEGs with ICC/MPF/gain-map metadata are outside the conservative profile. See [PNG privacy](png-privacy.md) and [JPEG privacy](jpeg-privacy.md).

Exports stage in a temporary file beside the chosen destination, flush it, then use no-clobber publication. Existing destinations, including the source and links to existing files, are refused. A collision after staging is also refused. Failed/cancelled staging is removed by the temporary-file owner. A process/OS crash may leave a temporary file; no case-store crash recovery or directory durability claim is made.

## Runtime privacy

There is no localhost HTTP listener, JavaScript file/network/shell plugin, or source-text execution. Tauri IPC is available only to the bundled main window. The CSP forbids inline script, `eval`, frames, objects and form submission, and allows exactly three remote origins, the registered imagery sources used by the Globe instrument (`https://gibs.earthdata.nasa.gov`, `https://tiles.maps.eox.at`, `https://basemap.nationalmap.gov`, [ADR 0008 §10](../adr/0008-d01-workspace-renderer.md#10-amendment-registered-online-imagery-in-the-webview-2026-11-03)); `'wasm-unsafe-eval'` is granted for the renderer's WebAssembly modules, which are bundled files, not strings. The document, privacy, witness and forensic tools make no network request. Native dialogs select the files; the frontend cannot supply an arbitrary path to a Rust command.

The Media instrument displays the held image through the `oia-snapshot` URI scheme (`http://oia-snapshot.localhost/<sha256>` under WebView2; `oia-snapshot://localhost/<sha256>` elsewhere), registered in `desktop.rs` and allow-listed in `img-src`. The handler answers only a 64-hex-digit path that equals the hash of the image snapshot currently held, with the bytes of that snapshot and `Cache-Control: no-store`; any other request is a 404. It reads no path, exposes no other state, and cannot be used to fetch a file the user did not open through the native dialog.

The Windows **WebView2 runtime may contact Microsoft independently of the page**. ADR 0008 observed background HTTPS connections in the renderer spike; this work does not claim to suppress them or establish network silence. The app's overview discloses this behavior. That observation belongs to the spike, not a new measurement of this build.

## Requirements and verification scope

This supplies bounded local-file portions of CASE-04/05, DOC-02/04, the structural byte-anchor subset of DOC-03 (session citation records checked against retained bytes), PRIVACY-01 and UX-01–UX-05, plus the session-only initial-account/revision portion of FIELD-02. It exercises relevant subsets of A02/A03/A13/A18 without completing those scenarios. Persistent cases and durable testimony, durable cancellation/retry/restart, workspace permissions, provenance envelopes/timestamps, sky sketches, regional/event attachment, actual explanation analysis, PDF/OCR, remote acquisition, semantic search, AI answers, reports and integrated A01–A03/A13/A18 acceptance remain open. No Lean theorem or Rust/Lean correspondence claim is introduced.

Three compact integration tests address concrete risks: source mutation changing an already-open search/anchor; hidden limits, malformed input and cancellation; and destructive export/late destination collisions plus output reinspection for PNG and JPEG. One desktop gate test verifies rejection of overlapping work and publication after cancellation. One witness adapter test verifies generated version wiring, rejected-edit atomicity, DTO exposure state, and initial-account preservation. One recreation adapter test verifies that reported wording is pinned verbatim to the chosen witness version with narrative line numbers, that unreported fields stay unknown and an assumption cannot replace a reported field, that a refused build (assumed reported field, control character, unheld version) keeps the previous prompt and version counter, and that saving a superseded prompt is refused. The desktop adapter also needs a manual interaction walkthrough; kernel tests alone do not establish a working app.

Validation results are recorded with the PR after local checks and the desktop walkthrough finish.
